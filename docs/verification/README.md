# SafeGori 최소 그래프 채팅: 실제 실행 결과

검증일: 2026-10-30 (Asia/Seoul)

구현 브랜치: `backend/minimal-graph-chat`. 실제 설정된 Upstage 모델은 `solar-pro4`이다.
FastAPI TestClient로 실제 `POST /api/chat` 핸들러를 호출했으며 DB와 LLM은 대역을 사용하지 않았다.
채팅 UI와 공개 API의 `{ "answer": "..." }` 형식은 유지했다. 브라우저 화면 캡처는 이번 기록에 포함하지 않았다.

## 확인한 범위

- 실제 DB 사례 집합·전체 건수·그룹별 건수·대책 빈도를 원본 JSON에서 독립 계산해 대조했다.
- 원본 사례번호와 내부 ID의 대응, 사례별 대책 연결과 최대 10건의 근거 제한을 확인했다.
- Jamal이 모델 설명을 각 인용 사례의 원문·대책과 대조해 검토하고 검토자·범위를 기록했다. 독립적인 현장 전문가 평가는 아니다.
- 별도의 읽기 전용 점검에서 건설업 전체 3,459건·공종 13개, 철근 작업 67건·단위작업 3개, 철근 반입 12건, 철근콘크리트 공사의 단위작업 15개 집계를 대조했다.
- 기인물 단독 조회 142건, 설명용 사례 제한에 대한 전체 건수의 독립성, 빈 단위작업·기인물 교집합을 확인했다.
- 단위 검증 18개와 프런트엔드 빌드를 통과했다. 범용 검색 성능·현장 유용성·기존 RAG 대비 우수성을 입증한 결과는 아니다.

## 재현

저장소 루트에서 다음 명령을 실행한다. 실제 Upstage 사용량이 발생하며 새 실행은 자동 검사 후 `pending_review`로 저장된다.

```bash
backend/.venv/bin/python scripts/verify_graph_chat.py --live
```

데이터는 [고용노동부가 공개한 SIF 아카이브](https://www.moel.go.kr/policy/policydata/view.do?bbs_seq=20260400196)를 프로젝트에 적재한 것이다.
검증 실행기는 외부 모델 호출 전에 DB 텍스트·식별자를 저장소의 공개 원본과 비교하고, 원본과 다른 내용은 전송하지 않는다.
DB·인덱스·설정은 변경하지 않았고 실제 스냅샷을 생성했다고 가정하지 않는다. 데이터·코드·모델이 바뀌면 같은 결과를 보장하지 않으므로 재검증이 필요하다.
