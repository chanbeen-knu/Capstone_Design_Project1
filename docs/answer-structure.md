# 사용자별 대표 질문과 답변 구조

원칙: **물은 것만 답하고, 나머지는 "추가 질문" 버튼으로 미룬다.**
한 답변에 표·사례·대책·그래프를 전부 펼치지 않는다. 숫자·사례 번호는 DB 결과에서만 (LLM은 문장만).

예시 수치는 2026-11-24 Aura(건설업 3,459건)에서 직접 확인한 값.

---

## 1. 사용자와 대표 질문

### A. 현장 작업자 (작업 직전, 휴대폰, 짧게)
| # | 대표 질문 | 묻는 것 | 그래프 경로 |
|---|---|---|---|
| A1 | 오늘 비계 위에서 일해. 뭐 조심해? | 지킬 것 3개 | 작업/기인물 → 사례 → 대책(통제위계 순) |
| A2 | 포크레인 옆에서 철근 내려. 위험한 거 있어? | 어떤 사고가 나는지 + 지킬 것 | 용어 사전 → 기인물 → 사례 → 재해종류·대책 |
| A3 | 안전대 꼭 걸어야 돼? | 안 하면 실제로 사고 났는지 | 유발요인(안전대 미체결) → 사례 |

### B. 현장 안전관리자 (위험성평가, TBM 준비, 근거 필요)
| # | 대표 질문 | 묻는 것 | 그래프 경로 |
|---|---|---|---|
| B1 | 굴착기 작업에서 어떤 사고가 많아? | 재해종류 분포 | 기인물 → 사례 → 재해종류 (예: 142건, 깔림 43건 30.28%) |
| B2 | 굴착기로 철근 반입할 때 대책 정리해줘 | 대책 목록 + 근거 | 작업+기인물 → 사례 → 대책 (예: 3건, 대책 6종) |
| B3 | 비계 추락 사고의 공학적 대책만 | 특정 위계 대책 | 기인물+재해종류 → 대책 → 통제위계 (예: 고유 122개) |
| B4 | 굴착기 작업 위험성평가에 쓸 유해위험요인은? | 원인 순위 | 기인물 → 사례 → 유발요인 |
| B5 | 추락방지시설 미설치로 인한 사고 몇 건? | 원인별 건수 | 유발요인 → 사례 (예: 1,406건) |

### C. 사무실 담당자 (안전교육·통계·보고서)
| # | 대표 질문 | 묻는 것 | 그래프 경로 |
|---|---|---|---|
| C1 | 가장 많이 반복된 사고 유형 3개 | 반복 패턴 | 사고 패턴 크기순 (예: 비계·추락·추락방지시설 미설치 168건) |
| C2 | 철근콘크리트 공사 사고를 작업별로 | 하위 분포 | 작업 계층 (예: 433건, 거푸집 213·콘크리트 120·철근 67·갱폼 33) |
| C3 | 건설기계 사고는 몇 건? / 맞음·부딪힘 계열은? | 상위 분류 건수 | 기인물 분류 614건 / 재해 상위분류 410건 |
| C4 | 중대재해처벌법 시행 이후에도 반복된 유형은? | 시기별 | 사례 → 연도 → 시기 + 패턴 |
| C5 | SIF-C-0455 설명해줘 | 사례 하나 | 사례 → 개요·원인·대책·소속 패턴(12건) |

### 범위 밖 (정중히 거절 + 할 수 있는 것 안내)
사고 확률 예측, 법령 해석, "우리 현장 안전한가" 판정, 브리핑 문서 생성.

## 2. 답변 유형 (질문 → 6가지로 수렴)

| 유형 | 해당 질문 | 결론 문장 | 본문 블록 (하나만) |
|---|---|---|---|
| **체크리스트** | A1, A2 | "이 작업에서는 이 3가지를 꼭 지키세요." | 대책 3개 (통제위계 순: 제거 → 공학 → 관리 → 보호구) |
| **분포** | B1, C2, C3 | "굴착기 사고 142건 중 깔림이 43건(30.28%)으로 가장 많았어요." | 상위 3개 막대/표 |
| **대책 종합** | B2, B3 | "3건에서 대책 6종이 나왔고, 3종은 2건에서 반복됐어요." | 대책 목록 (위계 배지 + "N건에서 확인") |
| **원인** | A3, B4, B5 | "추락방지시설 미설치가 원인인 사고는 1,406건이에요." | 상위 원인 3개 또는 해당 원인의 주요 기인물 3개 |
| **반복 유형** | C1, C4 | "가장 많이 반복된 유형은 비계·추락·추락방지시설 미설치(168건)예요." | 패턴 카드 3개 (이름·건수·대표 사례 1건) |
| **사례** | C5, "~사례 보여줘" | "철근 반입 사고는 12건이에요." | 사례 카드 5장 (카드 안 "더 보기"로 5건씩 추가) |

## 3. 답변 구조 (모든 유형 공통 뼈대)

```
① 결론 1문장        질문의 답 그대로 (숫자 또는 "이 3가지")         ← 코드가 DB 값으로 생성
② 본문 블록 1개      위 표의 블록 하나만                              ← DB 결과
③ 근거 칩            사례 번호 최대 3개 + "외 N건"                    ← DB 결과
④ (조건부) 매핑 표시  용어가 바뀐 경우만: "포크레인 → 굴착기"         ← 온톨로지 효과를 보이는 한 줄
⑤ 추가 질문 버튼 2~3개                                               ← 4절 규칙으로 생성
```

- LLM이 쓰는 건 ①의 말투 다듬기와 체크리스트 문장 요약뿐. 새 숫자 금지(기존 검증기 유지).
- **안 보여 주는 것**: 묻지 않은 표, 10건 사례 목록, 조회 그래프, 메타데이터. 모두 추가 질문이나 "더 보기"로.
- **0건일 때**: "없습니다"로 끝내지 않는다. 조건을 한 단계 위로 넓혀(상위 분류) 다시 조회하고,
  그래도 0건이면 "이 조건은 확인하지 못했습니다" + 넓힌 조건 버튼.

### 사용자별 조정 (같은 데이터, 보여 주는 양만 다름)
| | 작업자 | 관리자 | 사무실 |
|---|---|---|---|
| ① 결론 | 숫자 없이 행동 위주 | 건수·비율 포함 | 건수·비율 포함 |
| ② 블록 | 체크리스트 3개, 큰 글씨 | 표/목록 + 위계 배지 | 표 + 전체 수치 |
| ③ 근거 칩 | 숨김 (버튼으로) | 표시 | 표시 |
| ⑤ 추가 질문 | "실제 사고 보기" 위주 | "원인·위계별 대책" 위주 | "추이·반복 유형" 위주 |

사용자 구분: 화면 상단 토글(작업자/관리자/교육·사무), 기본값 관리자.

## 4. 추가 질문 구조

추가 질문은 **직전 답변의 조건(노드 ID)을 그대로 물려받아 한 가지만 바꾼 요청**이다.
버튼을 누르면 LLM 해석 없이 바로 템플릿을 실행한다 → 빠르고, 조건을 잃어버리지 않음
(오늘 고친 "근거 사례 설명해줘" 반복 문제의 근본 해결).

```json
{"label": "실제 사고 사례 보기", "intent": "cases",
 "scope": {"work": "UW:2.3.1 철근 반입", "object": "CO:굴착기"}}
```

### 유형별 추가 질문 (조건은 직전 답변에서 상속)
| 직전 답변 | 추가 질문 1 | 추가 질문 2 | 추가 질문 3 |
|---|---|---|---|
| 체크리스트 | 실제 사고 사례 보기 → 사례 | 왜 이런 사고가 나나 → 원인 | 이 작업에서 많은 사고 → 분포 |
| 분포 | 1위 재해종류 대책 → 대책 종합 (재해종류 추가) | 1위 사례 보기 → 사례 | 하위로 펼치기 → 분포 (한 단계 아래) |
| 대책 종합 | 근거 사례 보기 → 사례 | 공학적 대책만 → 대책 종합 (위계 추가) | 반복된 유형인가 → 반복 유형 |
| 원인 | 이 원인의 대책 → 대책 종합 (유발요인 조건) | 많이 나는 장비 → 분포 (group_by 기인물) | 사례 보기 → 사례 |
| 반복 유형 | 1위 대표 사례 자세히 → 사례 | 이 유형 대책 → 대책 종합 | 시행 이후에도 반복? → 반복 유형 (시기 추가) |
| 사례 | (추가 질문 버튼 없음) | 카드 안 "더 보기" → `POST /api/chat/cases`로 5건씩 | |

- 버튼 문구는 사용자 말투로 고정(코드 상수). 결과가 0건이 될 버튼은 미리 조회해 숨김.
- 사용자가 버튼 대신 직접 입력하면 기존처럼 LLM이 해석하되, 직전 답변의 조건 ID를 함께 넘김.

## 5. 응답 JSON (spec 02 형식에 맞춤)

```json
{
  "type": "measures",
  "conclusion": "3건에서 대책 6종이 나왔고, 3종은 2건에서 반복됐어요.",
  "block": {"kind": "measures", "rows": [{"text": "...", "level": "관리적 대책", "count": 2}]},
  "evidence": {"codes": ["SIF-C-0461", "SIF-C-0462", "SIF-C-0455"], "total": 3},
  "mapping": [{"from": "포크레인", "to": "CO:굴착기"}],
  "scope": {"work": "UW:2.3.1 철근 반입", "object": "CO:굴착기"},
  "follow_ups": [{"label": "근거 사례 보기", "intent": "cases", "scope": {"...": "..."}}],
  "relaxed": []
}
```

## 6. 구현 순서 (개선안 ①~⑥과 연결)
1. 개념 연결 확장 + BROADER 상향 조회 + 0건 처리 → 분포·원인 유형 (B1, B5, C2, C3)
2. 통제위계 필터·정렬 → 체크리스트·대책 종합 (A1, B2, B3)
3. 반복 유형 intent → C1, C4
4. 응답 JSON에 `conclusion / block / follow_ups / scope` 추가, 화면은 ①~⑤ 뼈대로
5. 위 예시 수치(142·43, 3·6, 122, 1,406, 168, 433, 614, 410)를 테스트 기대값으로 고정

## 7. 자주 묻는 질문별 답변 설계 (실데이터 예시)

### 7.0 효과적인 답변의 4가지 규칙
1. **가장 큰 사실 하나로 시작한다.** 상위 1개가 차지하는 비중을 결론으로.
   예: "비계 사망사고 196건 중 172건(88%)이 추락방지시설 미설치" → 이 한 줄이 체크리스트보다 강하다.
2. **목록은 3개까지.** 대책은 "반복된 횟수"로 고르고, 같으면 통제위계(제거 → 공학 → 관리 → 보호구) 순.
3. **사례는 대표 사례 1건.** 앞에서 아무거나 고르지 않고 사고 패턴의 대표 사례(`REPRESENTED_BY rank 1`)를 쓴다.
4. **"사망사고 기록 기준"임을 밝힌다.** 데이터가 SIF(사망·중대재해)뿐이라 "발생 빈도"가 아니라 "사망사고 중 비중".
   작업자에게도 쉬운 비율 한 마디("10건 중 9건")는 보여 준다 — 숫자 표·그래프만 숨김. (팀 확인 필요)

### 7.1 "비계 작업할 때 뭐 조심해?" — 가장 흔한 질문 (작업자·관리자)
**사용자가 원하는 것:** 지금 지킬 행동. 통계가 아님.

**답변 (관리자 보기)**
```
① 비계 사망사고 196건 중 172건(88%)이 추락방지시설 미설치 때문이었어요.
② 꼭 지킬 3가지
   1. 비계 조립·해체 때 안전난간을 먼저 설치하세요        [공학적]  56건에서 제시
   2. 난간 설치가 어려우면 안전대 부착설비 + 안전대 착용   [공학·보호구] 47건
   3. 작업발판 단부에 안전난간·안전방망 설치              [공학적]  35건
③ 대표 사례 SIF-C-1716 (2017, 시스템비계 3층에서 자재 인양 중 추락) 외 195건
⑤ [실제 사고 보기] [요즘도 이런 사고 나?] [다른 원인도 있어?]
```
**작업자 보기:** ①을 "비계 사망사고 10건 중 9건은 난간이 없어서 떨어진 사고예요."로, ②는 큰 글씨, ③ 숨김.

**꼬리 질문**
| 버튼 | 답변 방식 | 실데이터 |
|---|---|---|
| 실제 사고 보기 | 대표 사례 카드 1장 (개요 2줄·원인·대책) + "같은 유형 168건" | SIF-C-1716, 패턴 168건 |
| 요즘도 이런 사고 나? | 2022년(중대재해처벌법 시행) 이후 건수 한 줄 | 비계 30건, 그중 추락방지시설 미설치 24건 |
| 다른 원인도 있어? | 원인 2·3위 + 각 대책 1개 | 안전대 미체결 10, 발판·자재 파손·탈락 9 |

### 7.2 "굴착기 작업에서 어떤 사고가 많아?" (관리자)
**원하는 것:** 위험성평가에 적을 사고 유형과 그 원인.
```
① 굴착기 사망사고 142건 중 깔림이 43건(30%)으로 가장 많아요.
② 깔림 43 · 부딪힘 31 · 낙하 21   (막대 3개)
③ 대표 유형: 굴착기 · 깔림 · 차량·보행자 동선 관리 미흡 (27건, 대표 SIF-C-3397)
⑤ [깔림 사고 대책] [원인 순위] [사례 보기]
```
| 버튼 | 답변 방식 | 실데이터 |
|---|---|---|
| 깔림 사고 대책 | 대책 3개 (기인물=굴착기 + 재해종류=깔림) | — (구현 시 조회) |
| 원인 순위 | 유발요인 상위 3 | 동선 관리 미흡 53 · 운행경로 관리 미흡 30 · 줄걸이·양중 불량 29 |
| 사례 보기 | 유형별 대표 사례 3장 | SIF-C-3397, 2498, 0051 |

### 7.3 "굴착기 사고 예방대책 알려줘" (관리자·교육)
```
① 굴착기 사고에서 가장 많이 제시된 대책은 후방 카메라·센서·경보장치 부착(63건)이에요.
② 1. 후방 카메라·센서·경보장치 부착                         [공학적]   63건
   2. 장비 운행 경로와 분리된 작업자 안전통로 확보            [분류 전]  39건
   3. 근접 작업 시 안전거리 확보 + 유도자 배치                [관리적]   38건
⑤ [공학적 대책만] [이 대책이 나온 사례] [작업별로 보기]
```
- 통제위계가 없는 대책은 "분류 전"으로 표시 (규칙 매핑 미분류 8.8%, 숨기지 않음).

### 7.4 "철근 반입 사고 사례 보여줘" (전체)
```
① 철근 반입 중 사망사고는 12건이에요.
```

### 7.7 꼬리 질문의 흐름
사용자는 대부분 아래 순서로 깊어진다. 버튼은 **지금 단계의 다음 칸**을 우선 보여 준다.
```
무엇이 위험한가(분포) → 무엇을 지키나(대책) → 정말 일어났나(사례) → 왜 일어났나(원인) → 요즘도?(시기) → 교육자료(반복 유형·이미지 저장)
```
- 질문이 어느 칸에서 시작하든, 버튼 3개는 "다음 칸 1개 + 옆 칸 1개 + 근거(사례) 1개"로 구성.
- 이미 본 칸(같은 대화에서 같은 조건으로 답한 유형)의 버튼은 다시 보여 주지 않는다.
